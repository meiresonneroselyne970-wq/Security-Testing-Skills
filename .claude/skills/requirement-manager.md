# requirement-manager — 需求管理流程

**版本**: 1.0.0
**适用场景**: 需求全生命周期管理，支持 Bug/新功能/优化三类需求自动分类与优先级排序

---

## Trigger

当用户提到以下任何一种情况时触发此 skill：

- 需求管理 / 需求流程 / 需求评审
- 提交需求 / 新建需求 / 需求录入
- 需求分类 / 需求优先级 / 需求排序
- 需求排期 / 需求看板 / 需求跟踪
- 有没有重复需求 / 需求去重
- 需求紧急程度 / 需求评估
- requirement / feature request / bug tracking
- 产品需求 / 业务需求 / 优化需求

## 需求模板

### 提交格式

```yaml
title:           # 需求标题（一句话描述）
```

## AI 能力

### 1. 自动分类

根据需求描述自动推断类型：

| 分类 | 关键词/特征 | 示例 |
|------|-----------|------|
| 🐛 Bug | "报错"、"闪退"、"不显示"、"异常"、"数据不对" | "点击提交按钮后页面闪退" |
| ✨ 新功能 | "新增"、"支持"、"接入"、"开发"、"搭建" | "新增微信支付接入" |
| 🔧 优化 | "优化"、"改进"、"提升"、"重构"、"性能" | "优化列表滚动卡顿问题" |

**分类逻辑**：

1. 提取标题 + 描述中的关键词
2. 匹配三类特征词库
3. 输出分类 + 置信度
4. 置信度 < 0.7 时提示人工确认

### 2. 智能识别重复需求

**比对维度**：

| 维度 | 权重 | 方法 |
|------|------|------|
| 标题相似度 | 40% | 文本向量化（去掉停用词后的 TF-IDF 余弦相似度） |
| 关键词重叠度 | 30% | 提取核心名词，计算 Jaccard 系数 |
| 模块/页面 | 20% | 是否涉及同一功能模块或页面 |
| 来源/提出人 | 10% | 同一来源的重复提出 |

**判断规则**：

- 相似度 ≥ 80%：🚨 高度重复，建议合并
- 相似度 60%-79%：⚠️ 可能重复，需人工确认
- 相似度 40%-59%：💡 部分关联，建议关联而非合并
- 相似度 < 40%：✅ 独立新需求

### 3. 紧急程度评估

**评分维度**（总分 100）：

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 影响范围 | 30% | 全用户(30) / 核心用户(20) / 部分用户(10) / 个别用户(5) |
| 业务阻断 | 25% | 核心流程瘫痪(25) / 有替代方案(15) / 体验下降(8) / 无影响(0) |
| 时效要求 | 20% | 当天(20) / 本周(15) / 本月(10) / 无明确时限(5) |
| 用户反馈量 | 15% | >50人(15) / 10-50人(10) / <10人(5) / 无反馈(0) |
| 合规/安全 | 10% | 安全漏洞/合规红线(10) / 有安全风险(7) / 无影响(0) |

**优先级映射**：

| 总分 | 优先级 | 响应时间 | 排期策略 |
|------|--------|----------|----------|
| ≥ 80 | 🔴 P0 紧急 | 4 小时内 | 阻塞当前迭代，立即处理 |
| 60-79 | 🟠 P1 高优 | 24 小时内 | 当前迭代必须完成 |
| 40-59 | 🟡 P2 中优 | 本周内 | 纳入下个迭代 |
| < 40 | 🟢 P3 低优 | 本月内 | 按资源情况排期 |

## 评审检查清单

### Bug 评审

- [ ] 是否有复现步骤？复现率多少？
- [ ] 是否已定位根因？
- [ ] 影响范围和严重程度
- [ ] 修复成本和风险
- [ ] 是否有临时规避方案？
- [ ] 是否需要 Hotfix？

### 新功能评审

- [ ] 业务价值是否明确？
- [ ] 技术方案是否可行？
- [ ] 预估工作量（人天）
- [ ] 依赖方是否已对齐？
- [ ] 是否有技术风险？
- [ ] 是否需要架构评审？

### 优化评审

- [ ] 当前瓶颈是什么？
- [ ] 优化后的目标指标
- [ ] 改动范围和回归风险
- [ ] 是否有性能数据支撑？

## 执行流程

```
[1] 接收需求输入
     ├── 解析标题 + 描述
     ├── 提取结构化字段
     └── 生成需求 ID (REQ-YYYYMMDD-XXX)
     ↓
[2] AI 自动分析
     ├── 分类 → Bug / 新功能 / 优化（含置信度）
     ├── 去重 → 和已有需求比对，输出相似度
     └── 紧急度 → 计算优先级分数 (0-100)
     ↓
[3] 评审辅助
     ├── 生成评审摘要
     ├── 标注风险点
     └── 输出评审意见模板
     ↓
[4] 优先级排序
     ├── 列出所有待排期需求
     ├── 计算每个需求的优先级分数
     ├── 考虑依赖关系调整
     └── 输出推荐排序表
     ↓
[5] 排期分配
     ├── 关联目标版本/迭代
     ├── 指派负责人
     └── 输出排期看板
     ↓
[6] 状态跟踪
     ├── 待评审 → 已排期 → 开发中 → 测试中 → 已上线
     ├── 异常延期预警（超时未流转）
     └── 定期生成需求周报
```

## 工具使用

执行需求管理时使用以下工具：

1. **Grep** — 搜索已有需求标题/描述，用于去重比对
2. **Glob** — 查找现有需求文档（`.claude/requirements/**/*.json`）
3. **Read** — 读取相似需求的完整内容，确认是否真正重复
4. **Write** — 创建/更新需求文档
